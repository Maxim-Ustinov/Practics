# TenderScope — питч-дек

**Версия:** 1.0 · ноябрь 2026
**Статус продукта:** MVP собран end-to-end, публичных пользователей и выручки нет.
**Бренд:** TenderScope · «Умный поиск закупок для бизнеса»
**Палитра:** фон `#1F1F1F`, синий `#4F7CFF`, золотой `#FFB547`, шрифт Manrope.

---

## Для какого инвестора готовится дек

**Основной адресат — бизнес-ангел pre-seed / ранней стадии.**
Чек — **3 600 000 ₽ на 12 месяцев** (обоснование bottom-up на слайде 10). Ангел с опытом в B2B SaaS, финтехе или госзакупках: ему важен собранный продукт и проверяемая гипотеза юнит-экономики, а не текущая выручка.

**Почему не венчурный фонд.** У продукта пока нет публичных пользователей, выручки и повторяемости. Для фонда это слишком рано: дек честно показывает стадию «продукт есть, рынок не подтверждён». После 500–800 платящих Pro и 6–12 месяцев когортных данных этот же дек можно переработать в seed-версию.

**Грант — альтернативный сценарий.** Дек можно адаптировать под грант на НИОКР или поддержку МСП, но акцент придётся сместить на технологическую новизну и социальный эффект. Для гранта нужны смета по статьям и подтверждающие документы; текущая версия — коммерческий питч.

**Что инвестор должен вынести после дека:**
1. Проблема реальна и массова, но её цена пока гипотеза.
2. Продукт не «идея на салфетке»: пайплайн работает на живых данных.
3. Денег просят не на «допилить», а на запуск, дистрибуцию и проверку экономики.
4. Риски названы честно: нет traction, нет магазинов, нет боевых платежей.

## Как открыть и листать презентацию

1. Откройте `docs/pitch/pitch-deck.html` двойным кликом.
2. Либо из PowerShell в корне репозитория:
   ```powershell
   Start-Process .\docs\pitch\pitch-deck.html
   ```
3. Рекомендуемые браузеры: Chrome, Edge, Яндекс Браузер. Интернет не нужен: внешних картинок, шрифтов и CDN в файле нет.

**Управление:**

| Действие | Клавиши / элемент |
|---|---|
| Следующий слайд | `→`, `Пробел`, `Page Down`, кнопка `→` |
| Предыдущий слайд | `←`, `Page Up`, `Backspace`, кнопка `←` |
| Первый / последний слайд | `Home` / `End` |
| Индикатор | Счётчик `01 / 10` и полоса прогресса внизу |

**Сохранение в PDF:**

1. `Ctrl + P`.
2. Принтер — «Сохранить как PDF».
3. Ориентация — **альбомная**, формат — **16:9** (в CSS задано `16in × 9in`), поля — **нет**, масштаб — **100% / по умолчанию**.
4. Включите «Фоновая графика» / «Background graphics».
5. Должно получиться ровно **10 страниц**, по одному слайду на страницу.

> Если браузер добавляет пустую страницу, проверьте, что в диалоге печати выбран масштаб 100%, а не «по размеру страницы».

## Что является фактом

Всё ниже подтверждено текущим состоянием репозитория и `PROJECT_CONTEXT.md`:

- Кодовый MVP-пайплайн собран end-to-end: поиск → профиль/чат → лента → сохранённые → глубокий анализ. Это не утверждение о production-релизе или пользовательском E2E.
- Парсинг `zakupki.gov.ru` по 44-ФЗ и 223-ФЗ работает на живых данных.
- GPT превращает описание на естественном языке в фильтры поиска; чат меняет профиль.
- Быстрый AI-скоринг работает, стоимость ≈ **0,03 копейки за тендер** (замер по проекту).
- Глубокий анализ документов (PDF/DOCX/XLSX) работает на реальных документах: сводка, риски, требования, рекомендация.
- Аналитика заказчика: история контрактов по ИНН, статистика, AI-портрет.
- Реализованы лимиты Free/Pro на бэкенде.
- ЮKassa: backend/frontend scaffold готов, но кабинет, секреты и webhook не настроены; боевого платежа не было.
- Домен `tenderscope.ru` куплен, бренд TenderScope выбран.
- Публичных пользователей — **0**, выручки — **0**, листингов в магазинах — **нет**; интеграционные компоненты push есть в коде, но фактическая доставка на устройстве не подтверждена.

**Traction в этом деке — это продукт, а не пользователи.** Мы не показываем выдуманные логотипы, отзывы, партнёров, награды или имена.

## Ограничения текущей версии

- Дек не содержит финансовой модели в Excel: только bottom-up бюджет и юнит-экономика как гипотеза.
- Нет юридических документов, cap table и деталей сделки — это следующий этап после первого интереса.
- Нет обещаний по срокам релиза в магазинах: они зависят от модерации и закрытия технических блокеров.
- Все оценки конкурентов качественные, не основаны на закрытых данных конкурентов.
